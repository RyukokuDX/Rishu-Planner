# 大学履修登録支援Webアプリ 要件定義書

## 1. 概要

### 1.1. アプリケーションの目的
本アプリケーションは、大学生が次学期に履修する授業を計画し、最適な時間割を作成することを支援するWebアプリケーションである。複雑な履修要件や授業の重複を考慮しながら、直感的な操作で時間割のシミュレーションを行うことを可能にする。

### 1.2. ターゲットユーザー
- 履修登録期間中に、効率的に時間割を組みたい大学生
- 複数の授業の組み合わせを試し、最適な選択をしたい学生
- 卒業要件や取得単位数を意識しながら履修計画を立てたい学生

### 1.3. 開発背景
大学の公式な履修登録システムは、多くの場合、授業の検索や時間割の全体像の把握がしにくいという課題がある。学生はスプレッドシートや手書きで時間割案を複数作成するなど、煩雑な作業を強いられている。本アプリケーションは、これらの課題を解決し、視覚的で使いやすいインターフェースを提供することで、学生の履修登録における負担を軽減することを目的とする。

## 2. 機能要件

### 2.1. 必須機能 (Minimum Viable Product)
まず最低限実装すべき機能です。

| 機能名 | 機能概要 |
| :--- | :--- |
| **選択可能な講義リストの表示機能** | 各時間のマスをクリックすると選択可能な授業リストが表示される。 |
| **時間割作成機能1** | 授業リストのチェックボックスをクリックするとその授業の時間に追加できる。 |
| **時間割の重複チェック機能** | 追加しようとしている授業が、既に登録済みの授業と時間的に重複する場合に警告を表示する。 |
| **取得単位数の自動計算機能** | 時間割に追加した授業の単位数を自動で合計し、表示する。 |
| **時間割の保存・復元機能** | 作成した時間割をブラウザに一時保存し、いつでも再開できる。また、ファイルとしてエクスポート/インポートすることで、データのバックアップや他デバイスへの移行を可能にする。 |

### 2.2. 推奨機能
必須機能が完成したら、次に追加したい便利な機能です。

| 機能名 | 機能概要 |
| :--- | :--- |
| **卒業要件管理機能** | ユーザーが自身の学部・学科の卒業要件（必修、選択必修など）を設定し、履修計画が要件を満たしているか進捗を確認できる。 |
| **レスポンシブデザイン** | PC、タブレット、スマートフォンなど、異なる画面サイズでも最適化された表示で利用できる。 |
| **作成した時間割の共有機能** | 作成した時間割のURLを発行し、友人と共有して予定を調整できる。 |
| **講義データの検索機能** | 講義名、教員名、開講学部、曜日時限など、様々な条件で授業を検索できる。 |
| **時間割作成機能2** | 検索した授業をドラッグ＆ドロップなどの直感的な操作で、時間割表に追加できる。 |

### 2.3. 任意機能 (Nice to have)
さらにアプリを魅力的にするための追加機能です。

| 機能名 | 機能概要 |
| :--- | :--- |
| **空きコマ検索機能** | 時間割の中で空いている時間（空きコマ）を指定し、その時間帯に開講されている授業を検索できる。 |
| **シラバス連携機能** | 各授業の詳細情報から、大学の公式シラバスページへ直接リンクする。 |
| **お気に入り・気になるリスト機能** | 履修を迷っている授業を「気になるリスト」に登録し、後から比較検討できる。 |

## 3. 非機能要件
アプリの品質に関する要件です。

| 項目 | 内容 |
| :--- | :--- |
| **ユーザビリティ** | - 初めて使う人でも直感的に操作方法がわかるシンプルなUI。<br>- 授業の追加・削除が少ない手数でスムーズに行える。 |
| **パフォーマンス** | - 講義データの検索結果は2秒以内に表示される。<br>- 時間割への授業の追加・削除は、1秒以内に画面に反映される。 |
| **データの正確性・信頼性** | - 表示される講義データ（時間、教室、単位数など）は、大学の公式情報と一致していること。<br>- ユーザーが作成した時間割データが意図せず消失しないこと。 |
| **セキュリティ** | - ユーザーアカウント情報を利用する場合、パスワードはハッシュ化してデータベースに保存する。<br>- SQLインジェクションやクロスサイトスクリプティング（XSS）などの基本的な脆弱性対策を講じる。 |
| **互換性** | - 主要なWebブラウザ（Google Chrome, Firefox, Safari, Microsoft Edge）の最新版で正常に動作すること。 |

## 4. 画面構成案

- **時間割作成画面 (メイン画面)**: 左側に時間割表、右側に選択可能な講義リストを配置する。アプリの核となる画面。
- **講義詳細モーダル**: 検索結果リストや時間割表の授業をクリックした際に、授業の詳細情報（シラバス、口コミなど）を表示するポップアップ画面。
- **設定画面**: 卒業要件の管理など、アプリケーション全体の設定を行う画面。

## 5. 想定技術スタック (一例)

- **フロントエンド**: React, Vue.js, Svelte (UIを構築するためのライブラリ/フレームワーク)
- **バックエンド**: Node.js (Express), Python (Django, Flask), Ruby (Rails) (サーバー側の処理を記述)
- **データベース**: PostgreSQL, MySQL, MongoDB (講義データやユーザーデータを保存)
- **インフラ/ホスティング**: Vercel, Netlify, Heroku, AWS, GCP (作成したアプリを公開する場所)
- **データ収集**: Python (Beautiful Soup, Scrapy) などを用いて大学の公開情報から講義データをクローリング・スクレイピング（※大学の規約を要確認）
