# 週間予定管理Webアプリ 要件定義書

## 1. 概要

### 1.1. アプリケーションの目的
本アプリケーションは、大学生が授業を正しく計画し，充実した学生生活を送ることを支援するWebアプリケーションである．

### 1.2. ターゲットユーザー
- 複数の予定を抱え、効率的なスケジュール管理を求めている大学生
- スマートフォンとPCの両方でスケジュールを確認・編集したい学生

### 1.3. 開発背景
大学生のスケジュールは、固定の授業に加えて、流動的なサークル活動やアルバイト、友人との約束など多岐にわたる。既存のカレンダーアプリでは管理が煩雑になりがちなこれらの予定を、1週間の時間割形式で視覚的に分かりやすく管理できるツールを提供することで、この課題を解決する。

## 2. 機能要件

### 2.1. 必須機能 (Minimum Viable Product)
まず最低限実装すべき機能です。

| 機能名 | 機能概要 |
| :--- | :--- |
| **週間カレンダー表示機能** | 1週間分の予定を時間割（タイムテーブル）形式で表示する。 |
| **予定の登録機能** | 日時、タイトル、カテゴリを指定して新しい予定を作成できる。 |
| **予定の編集・削除機能** | 登録済みの予定の内容を編集したり、不要な予定を削除したりできる。 |
| **予定のカテゴリ分け機能** | 「授業」「サークル」「バイト」「プライベート」など、予定の種類をカテゴリで分類できる。 |
| **カテゴリの色分け表示機能** | 設定したカテゴリごとに予定の色が変わり、一目で何の予定か識別できる。 |

### 2.2. 推奨機能
必須機能が完成したら、次に追加したい便利な機能です。

| 機能名 | 機能概要 |
| :--- | :--- |
| **繰り返し予定の登録機能** | 「毎週月曜2限」のような定期的な予定を一度に登録できる。 |
| **ToDoリスト機能** | 授業の課題や買い物リストなど、日付に縛られないタスクを管理できる。 |
| **レスポンシブデザイン** | PC、タブレット、スマートフォンなど、異なる画面サイズでも最適化された表示で利用できる。 |
| **通知機能** | 予定の開始前（例: 15分前）にブラウザやメールで通知を受け取れる。 |

### 2.3. 任意機能 (Nice to have)
さらにアプリを魅力的にするための追加機能です。

| 機能名 | 機能概要 |
| :--- | :--- |
| **予定の共有機能** | 作成した予定を友人など他のユーザーと共有できる。グループでの予定調整に利用する。 |
| **空き時間検索機能** | 指定した条件（例: 平日の午前中）に合致する空き時間を自動で検索・表示する。 |
| **外部カレンダー連携機能** | GoogleカレンダーやAppleカレンダーと同期し、予定をまとめて管理できる。 |
| **テーマカスタマイズ機能** | アプリの見た目をダークモードや好みのカラーテーマに変更できる。 |

## 3. 非機能要件
アプリの品質に関する要件です。

| 項目 | 内容 |
| :--- | :--- |
| **ユーザビリティ** | - 初めて使う人でも直感的に操作方法がわかるシンプルなUI。<br>- ドラッグ＆ドロップで予定の時間を変更できるなど、少ない手数で操作が完了する。 |
| **パフォーマンス** | - ページの表示は3秒以内に完了する。<br>- 予定の登録や更新などの操作は、1秒以内に応答がある。 |
| **信頼性** | - 登録した予定データがユーザーの意図しない形で消失しないこと。<br>- 定期的なデータバックアップを行う。 |
| **セキュリティ** | - パスワードはハッシュ化してデータベースに保存する。<br>- SQLインジェクションやクロスサイトスクリプティング（XSS）などの基本的な脆弱性対策を講じる。 |
| **互換性** | - 主要なWebブラウザ（Google Chrome, Firefox, Safari, Microsoft Edge）の最新版で正常に動作すること。 |

## 4. 画面構成案

- **ログイン/新規登録画面**: ユーザーがサービスを利用開始するための画面。
- **週間カレンダー画面 (メイン画面)**: アプリの核となる、1週間の予定が表示される画面。ここから予定の追加や編集を行う。
- **予定作成/編集モーダル**: 予定の詳細（タイトル、日時、カテゴリ、メモなど）を入力するためのポップアップ画面。
- **設定画面**: アカウント情報、カテゴリの管理（追加・編集・削除）、通知設定などを行う画面。

## 5. 想定技術スタック (一例)

- **フロントエンド**: React, Vue.js, Svelte (UIを構築するためのライブラリ/フレームワーク)
- **バックエンド**: Node.js (Express), Python (Django, Flask), Ruby (Rails) (サーバー側の処理を記述)
- **データベース**: PostgreSQL, MySQL, MongoDB (予定データを保存)
- **インフラ/ホスティング**: Vercel, Netlify, Heroku, AWS, GCP (作成したアプリを公開する場所)
